# 반걸음 WebLLM 모델 비교 결과

Nov 23, 2026 · @박진

## 요약과 추천

지시문을 고치고 규칙이 모르는 목표 10개를 더해 다시 비교했다(목표 20개, 40점 만점). **Qwen3.5-4B는 31점으로 기본 규칙(21점)을 넘었고, Chrome 내장 AI(36점)에 다가갔다.** 2B는 13점에 그쳤다.

1차에서 기본 규칙이 앞섰던 것은 시험 목표가 규칙을 다듬을 때 쓴 목표였기 때문이다. 규칙이 모르는 새 목표에서 기본 규칙은 20점 중 4점이었다.

**추천**

1. **WebLLM 기본 모델은 Qwen3.5-4B로 한다.** 받는 크기 약 2.3GB, GPU 메모리 약 3.9GB라 사실상 PC용이다. 설정 화면에 “PC 권장, 약 2.3GB”를 적는다.
2. **2B와 0.8B는 넣지 않는다.** 휴대폰용 가벼운 모델을 두면 기본 규칙보다 나쁜 결과를 준다.
3. **기본 규칙을 먼저 고친다.** 휴대폰 사용자는 대부분 기본 규칙만 쓴다. 새 목표에서 “중고 노트북 끝냈을 때의 모습 한 문장으로 적기”처럼 어색한 단계가 나오는 것이 가장 큰 문제다.

품질 점수는 Claude가 매긴 것이고, 한 번씩만 돌렸다. “원본 결과 (2차)” 탭을 보고 다르게 보이는 점수는 댓글로 알려 주세요.

## 2차 비교 (지시문 수정 후, 목표 20개)

새 목표에서는 기본 규칙이 4점, Chrome 내장 AI가 18점, 4B가 14점이다. AI의 가치는 규칙이 모르는 목표에서 나온다.

**바꾼 것**: 지시문에 “첫 단계는 5\~15분”, “본인이 할 행동”, “목표 문장을 그대로 쓰지 않기”, “숫자는 필요할 때만”, “예시는 형식만 참고”를 넣었다. 지시문·분석 줄·목표를 그대로 옮긴 단계와 예시를 조금 바꿔 베낀 답을 거르고, “정리”를 방 정리로 쪼개던 문제를 고쳤다.

**기존 10개에서 달라진 점**: 4B 13→17점, Chrome 내장 AI 16→18점으로 올랐다. 2B는 10→8점으로 내려갔다. 책 읽기에서 같은 문장을 끝없이 반복했고 블로그 글은 날짜만 나열했다. 2B(신발장)와 4B(엑셀) 답 하나씩은 거르기에 걸려 기본 규칙으로 대신했다.

후보 모델 3개와 기준선 2개가 같은 목표 10개를 같은 조건으로 나눴다. 지시문·예시·응답 형식·답 해석·결과 검사는 실제 앱 코드(`src/ai/prompt.ts`, `refine.ts`)를 그대로 썼다.

| --- | --- | --- |
| 후보 (작음) | Qwen3.5-0.8B (q4f16) | 휴대폰용으로 쓸 만한지 |
| 후보 (중간) | Qwen3.5-2B (q4f16) | 기본값 1순위 |
| 후보 (큼) | Qwen3.5-4B (q4f16) | PC 전용 선택지로 둘 만한지 |
| 기준선 | 기본 규칙 | AI 없이 쓰는 현재 경로 |
| 기준선 | Chrome 내장 AI | 데스크톱 Chrome의 현재 AI 경로 |

- 후보는 WebLLM 0.2.89 목록에서 가장 새로운 Qwen 계열(Qwen3.5)로 골랐다. 처음 계획한 Qwen2.5보다 새 버전이다.

- 시험용 목표 10개: 다음 주까지 부모님 생신 선물 사기, 토익 900점 받기, 매일 20분 책 읽기, 여권 재발급 신청하기, 신발장 정리, 11월 20일까지 블로그 글 쓰기, 엑셀 함수 배우기, 집주인에게 보일러 수리 요청하기, 친구 결혼식 축사 준비, 동네 봉사활동 시작하기.

- 품질 평가는 Claude가 했다. 기준: 첫 단계를 지금 바로 할 수 있는가, 단계가 목표에 맞고 구체적인가, 한국어가 자연스러운가. 좋음 2점 · 보통 1점 · 나쁨 0점, 목표 10개 합계 20점 만점.

## 관찰한 점

작은 모델의 가장 큰 문제는 “맞춤 예시”를 베끼는 것이다. 0.8B는 10개 중 약 5개, 4B도 2개에서 예시 답을 거의 그대로 냈다. 예시가 기본 규칙 계획이라, 베끼면 점수는 나오지만 AI를 쓴 의미가 없다.

- **예시 베끼기**: 지금 검사는 방 정리 예시를 똑같이 쓴 경우만 걸러낸다. “집 근처 쓰레기 버리기”처럼 조금 바꾼 것과 맞춤 예시를 베낀 것은 통과한다.
- **지시문·분석 줄을 단계로 냄**: 0.8B가 두 번(“사기·고르기·대상 …”, “목표치를 3\~7개로 나누기”). 지금 검사는 지시문을 통째로 돌려준 경우만 걸러낸다.
- **“3개” 덧붙이기**: 4B는 “후보 3개 찾기” 같은 예시 말투를 모든 하위 단계에 붙였다(“답변 내용 3 줄 적기”).
- **큰 첫 단계**: 토익처럼 큰 목표는 AI가 모두 큰 묶음으로 나눴다. “첫 단계는 15분 이하”라는 앱의 원칙이 지시문에 없어 모델이 모른다.
- **`refine`의 잘못된 짐작**: 첫 단계가 15분을 넘으면 말에 맞는 패턴으로 쪼개는데, “엑셀 기본 개념 정리”의 “정리”를 방 정리로 읽어 “한 구역만 정하기”를 붙였다. AI와 기본 규칙 양쪽에 영향을 준다.
- **기본 규칙 자체의 틈**: 신발장 정리에 방 정리 템플릿, 축사에 슬라이드 단계, 봉사활동에 일반 단계를 썼다. 이 세 곳에서는 Chrome 내장 AI가 더 나았다.
- **속도는 문제가 아니다**: 모델을 받아 둔 뒤에는 불러오기 2\~6초, 답 평균 2\~6초로, 앱의 60초 제한에 한 번도 걸리지 않았다. 다만 0.8B의 첫 답은 23.7초로, 처음 한 번은 준비 시간이 더 든다.

## 다음 단계

2차 비교까지 지시문·답 거르기·`refine`의 “정리” 문제는 고쳤다. 남은 일은 아래 순서다.

- [x] 기본 규칙: 모르는 목표에서 말이 깨지는 문제 고치기 (“… 끝냈을 때의 모습”, “식비 원”, “일어나는 만들기”, 목표치 유형의 “연습 25분”)
- [x] `refine`: 맞는 패턴이 없으면 첫 단계에 “필요한 것 챙기기 / 앞부분부터 시작하기”를 붙이지 않기
- [ ] (필요 없음: 깨진 JSON은 없었다) 깨진 JSON 답 살리기 (`]]`처럼 괄호가 어긋난 경우)
- [ ] WebLLM 엔진을 Qwen3.5-4B 하나로 구현 (설정에서 받기·진행률·지우기, “PC 권장, 약 2.3GB” 안내)
- [ ] Android Chrome에서 4B가 도는지 확인 (안 되면 휴대폰에서는 WebLLM을 숨김)

앞의 두 가지는 고쳤다. 일반 유형은 대상 없이 “해야 할 일 떠오르는 대로 적기 → 가장 쉬운 일 하나 고르기 → 15분 해 보기”로 바꿨다. “팔기” 유형을 새로 만들었다. “줄이기·올리기”는 숫자가 있을 때만 목표치로 본다. “연말정산”의 연말은 마감으로 읽지 않는다. “당근에 팔기”처럼 장소는 대상에서 뺀다. “공부”만으로는 시험 템플릿을 쓰지 않는다. 고친 뒤 새 목표 10개와 처음 보는 목표 10개에서 앞의 깨진 문장은 사라졌다. 습관 유형도 “언제 어디서 할지 정하기 → 첫 1회 해 보기 → 이번 주 토요일에 해 보기”처럼 활동 이름을 넣지 않고, 횟수에 맞는 문장을 쓰게 고쳤다. 점수는 다시 매기지 않았다.

기본 규칙을 고치면 AI가 없는 휴대폰 사용자가 가장 크게 좋아진다. 설계 문서의 “실제 Chrome 내장 AI 결과 확인” 항목은 이 비교로 끝낼 수 있다(20개 모두 보통 이상, 그중 16개 좋음).
