가장 큰 변경은 순서다. **웹 버전을 먼저 완성하고, Android 앱은 그다음 단계로 미룬다.**

표기 규칙은 세 가지다. **[결정]**은 정해진 것, **[제안]**은 Claude가 제안해 확인이 필요한 것, **[결정 필요]**는 아직 열린 것이다. 열린 항목은 문서 끝에 모았다.

## 제품 목표

반걸음은 큰 목표를 지금 바로 할 수 있는 작은 단계로 쪼개고, 하나씩 끝내도록 돕는 도구다. **[결정]**

**대상 사용자 [제안]**: 목표가 커서 시작을 미루는 사람. 할 일 앱은 쓰지만 “보고서 쓰기” 같은 항목 앞에서 멈추는 사람.

**해결하려는 문제 [제안]**: 목표가 크면 첫 동작이 보이지 않아 시작하지 못한다. 반걸음은 다음 한 걸음을 항상 보여 준다.

### 핵심 원칙

- **모든 처리는 기기 안에서 [결정]**: AI를 포함해 서버, 계정, API 키가 없다. 데이터는 사용자 기기에만 있다.
- **AI 없이도 끝까지 쓸 수 있다 [결정]**: AI를 못 쓰는 환경에서는 규칙 엔진, 템플릿, 직접 입력으로 같은 흐름을 제공한다.
- **오프라인 우선 [결정]**: 한 번 열고 나면 네트워크 없이 동작한다.
- **다음 할 일 하나에 집중 [제안]**: 화면의 중심은 트리 전체가 아니라 지금 할 한 단계다.
- **벌주지 않는 동기 부여 [제안]**: 완료는 크게 축하하고, 밀린 일이나 끊긴 기록은 경고하지 않는다.
- **디자인은 힐링되는 느낌 [결정]** (todo.md): 효과는 너무 화려하지 않게, 글꼴은 무료 폰트. 예외로 목표 전체 완료 축하만 화려하게 한다(2026-11-23).

### 배포 대상 [결정, 2026-11-23]

공개 배포용이다. GitHub Pages(공개 저장소, 무료)로 웹에 배포하고, 주소를 아는 누구나 쓸 수 있다. 처음에는 Replit으로 정했다가 같은 날 비용 때문에 GitHub Pages로 바꿨다.

### 성공 기준 [제안]

- 처음 쓰는 사람이 1분 안에 목표 하나를 쪼개고 첫 단계를 체크한다.
- AI가 없는 브라우저에서도 같은 흐름이 막힘없이 끝난다.
- 데이터가 사라지지 않는다: 새로고침, 브라우저 재시작, 앱 업데이트 후에도 그대로다.

## 로드맵

웹 v1을 끝낸 뒤 같은 코드로 Android 앱을 만든다. 각 단계는 완료 기준을 모두 만족해야 다음으로 넘어간다.

1. **1단계: 웹 v1 [결정]**. 브라우저와 설치형 PWA로 쓴다. **← 지금 여기 (M1~M5 대부분 완료, 첫 배포 완료, 휴대폰 확인 남음)**
   1. 완료 기준: 웹 v1 범위의 기능이 모두 동작한다.
   2. 완료 기준: 저장소가 IndexedDB로 바뀌고, 기존 localStorage 데이터가 손실 없이 옮겨진다. ✅
   3. 완료 기준: 트리 규칙과 저장 계층에 자동 테스트가 있고 모두 통과한다. ✅
   4. 완료 기준: 배포된 HTTPS 주소에서 설치하고, 오프라인으로 다시 열어도 동작한다. (배포됨, 휴대폰 설치·오프라인 확인 남음)
2. **2단계: Android 앱 [결정, 시기 미정]**. 웹 코드를 Capacitor로 감싸고 기기 내 AI를 더한다.
   1. 시작 조건: 1단계 완료, 사용자 PC에 Android Studio 빌드 환경 준비.
3. **이후 후보 [제안]**: 활동 기록과 통계, 목표 보관함, 기기 간 동기화. 동기화는 “기기 안에서” 원칙과 부딪히므로 따로 결정한다.

## 화면 구성

memo.md의 화면 구조를 바탕으로 2026-11-09에 개편했다. 주소(# 뒤)로 화면을 바꾸므로 휴대폰과 앱의 뒤로 가기가 화면 사이를 오간다.

### 사이드바

휴대폰에서는 왼쪽 위 ☰로 여는 서랍이다.

- 홈
- 진행 중인 일 (개수)
- 완료된 일 보관함 (개수). memo.md에서는 설정 아래였지만 2026-11-09 사용자 요청으로 진행 중인 일 아래로 옮겼다.
- 설정: AI 설정, 템플릿 설정, 백업과 저장 공간, 화면 설정(축하 효과)

### 주소

`#/` 홈 · `#/goals` 진행 중인 일 · `#/goal/<id>` 일 페이지 · `#/new` 새 목표 · `#/archive` 보관함 · `#/settings/ai` · `#/settings/templates[/<id|new>[?from=기본id]]` · `#/settings/data` · `#/settings/display`

새 목표를 만들면 새 목표 화면은 방문 기록에서 대체되어 뒤로 가면 목록으로 간다. 일을 지우면 목록으로 가고, 실행 취소하면 그 일 페이지로 돌아온다.

### 홈

memo.md의 의도: 지금 진행 중인 일 하나의 한 단계만 가운데에 크게 보여 준다.

- 고정한 일이 진행 중이면 그 일, 아니면 가장 최근에 손댄(updatedAt) 진행 중인 일의 다음 단계를 보여 준다. 카드에는 일 제목 → 상위 단계 경로 → 다음 단계 → 예상 시간 → “끝냈어요”가 있다.
- 카드를 누르면 그 일 페이지로 간다.
- “끝냈어요”를 누르면 단계를 완료하고 카드가 다음 단계로 바뀐다. 마지막 단계면 축하 창이 뜨고, “○○을 모두 끝냈어요. 보관함으로 옮겼어요.” 알림(실행 취소 가능)과 함께 다음 진행 중인 일로 넘어간다.
- “＋ 새로 만들기” 버튼, 다른 일이 있으면 “진행 중인 일 n개 더 보기” 링크.
- **홈에 고정**: 일 페이지 아래 “홈에 고정 / 홈 고정 해제”. 고정한 일을 끝내거나 지우면 최근 일로 넘어가고, 다시 진행 중이 되면 돌아온다.
- 진행 중인 일이 없으면 새 목표 안내를 보여 준다.
- 홈에 진행도 바와 “다른 일 진행하기” 버튼(memo.md)은 넣지 않는다 (2026-11-23 결정). 홈은 단계 하나에 집중하고, 다른 일은 “진행 중인 일 n개 더 보기”나 홈 고정으로 고른다. 버튼은 한 번 만들었다가 뺐다. 실제로 써 보다가 지금 할 수 없는 단계가 홈에 자주 걸리면 다시 검토한다.

### 진행 중인 일 / 보관함

- 진행 중인 일: 제목만 있는 목록(최근에 손댄 순)과 “새 목표” 버튼. 누르면 일 페이지.
- 완료된 일 보관함: 단계가 하나 이상 있고 모두 끝난 일(계산값, DB 필드 없음). 최근 완료 순, 완료 날짜 표시. 단계를 해제하면 진행 중으로 돌아간다.

### 일 페이지

- 목표 제목, 메모, 보상(“다 끝내면 …”)을 눌러서 바로 고친다.
- 진행률 바, 남은 시간, 다음 할 일 카드와 “끝냈어요”.
- 단계 트리: 체크, 접기·펼치기, 아래 “단계 추가”, “단계 더 제안받기”.
- **편집 모드**: 단계 목록 위 “편집” 버튼. 편집 중에만 단계 ⋯ 메뉴(더 쪼개기, 하위 단계 추가, 위·아래, 들여·내어쓰기, 예상 시간, 삭제), 단계 제목 고치기, “이 목표 삭제”가 나온다. 편집 모드는 저장하지 않으며 들어올 때마다 평소 모드다.
- “홈에 고정”, “템플릿으로 저장”은 항상 보인다.

### 새 목표

- 탭 3개: 자동으로 나누기, 템플릿(내 템플릿이 먼저), 직접 적기. 모두 미리 보기(단계 수, 총 시간)를 거쳐 만든다.
- 자동·템플릿 결과는 “고쳐서 쓰기”로 직접 적기 탭에 옮겨 고칠 수 있다(고치지 않으면 원래 source, 고치면 manual). 목표를 바꾸면 이전 나누기 결과로는 만들 수 없다.
- 나누는 중 “멈추기”, 결과 아래 “○○로 나눴어요” 또는 “(이유) 대신 기본 규칙으로 나눴어요”와 “읽어 낸 정보”.
- “다 끝내면 나에게 줄 보상 (선택)” 칸.
- **직접 적기 형식**: 한 줄 = 단계, 들여쓰기(공백·탭·전각 공백) = 하위, 글머리표(-, *, •, 1., 1)) 제거, 줄 끝 “10분”·“(1시간 30분)”·“[2시간]” = 예상 시간.

### 템플릿 설정

내 템플릿 만들기·고치기·삭제(두 번 눌러 확인), 기본 템플릿 “복사해서 고치기”. 이름, 한 줄 설명, 자동 나누기 키워드, 단계(직접 적기 형식). 일 페이지의 “템플릿으로 저장”은 지금 단계 구조(리프 시간 포함, 완료 여부 제외)로 템플릿을 만들고 편집 화면으로 간다.

### 시각 스타일

회녹색 바탕, 잉크색 글씨, 완료는 청록, 다음 할 일은 황금색. 반쯤 채운 원(HalfMark)이 상징이다. 다크 모드, 터치 크기 44px, 안전 영역, 동작 줄이기에 대응한다. 한국어는 띄어쓰기 단위로 줄을 바꾼다(`word-break: keep-all`).

## 도메인 규칙

완료 여부는 리프만 저장하고 부모는 항상 자식에서 계산한다. 모든 쓰기 함수(`src/db/ops.ts`)는 아래 규칙을 지키고, 각 규칙에는 자동 테스트가 있다.

### 불변식 [결정]

1. 자식이 있는 단계의 `doneAt`은 항상 null이다.
2. 리프에 자식이 생기면(쪼개기, 하위 추가, 들여쓰기) 그 단계의 `doneAt`은 null이 된다.
3. 마지막 자식이 지워지거나 빠져나가 리프로 돌아가면 `doneAt`은 null이다. 예전 값이 되살아나지 않는다.
4. 부모를 체크하면 하위의 미완료 리프를 한꺼번에 now로, 해제하면 모두 null로 바꾼다. **이미 완료된 리프의 완료 시각은 그대로 둔다**(통계용, 2026-11-09 변경).
5. 단계를 지우면 하위 전체가 함께 지워진다. 목표를 지우면 그 목표의 단계가 모두 지워진다.
6. 모든 쓰기는 하나의 트랜잭션 안에서 일어나고, 목표의 `updatedAt`을 함께 갱신한다. 예외: 접기, 축하·보상 기록은 화면 상태에 가까워 `updatedAt`을 바꾸지 않는다.

### 계산 (`src/model/tree.ts`)

- **단계 완료**: 리프는 `doneAt != null`, 부모는 자식이 모두 완료.
- **진행률**: 완료된 리프 수 ÷ 전체 리프 수.
- **남은 시간**: 완료되지 않은 리프의 `minutes` 합과 시간 미정 리프 수.
- **다음 할 일**: 순서대로 깊이 우선 탐색해 처음 만나는 미완료 리프(상위 경로 포함). 접힌 단계 안도 포함한다.
- **목표 분류** (`src/model/goals.ts`): 단계가 하나 이상이고 모두 끝났으면 완료, 아니면 진행 중.

### 순서

- 새 형제는 끝에 붙고 `order` = 형제 중 최댓값 + 1000.
- 위·아래 이동은 이웃 형제와 `order` 값을 맞바꾼다.
- 들여쓰기: 바로 위 형제의 마지막 자식이 되고, 새 부모를 펼친다.
- 내어쓰기: 부모 바로 다음 자리(부모의 형제)로 올라간다.

### 그 밖의 처리

- 부모를 찾을 수 없는 단계는 최상위로 표시한다(데이터 손실 방지).
- 제목을 비워서 저장하면 오류 없이 원래 제목으로 돌아간다. 메모와 보상은 비울 수 있다.
- **쪼갤 때 minutes**: 쪼갠 결과에 시간이 없으면 부모의 시간을 패턴 비율로 나눠 준다(`withMinutes`, `splitByPattern`). 이전 버전의 “쪼갤 때 minutes가 버려지는” 문제는 해결됐다.

## AI 분해

### 엔진 순서

- **웹**: Chrome 내장 AI → WebLLM → 기본 규칙. 현재 코드는 `ENGINES = [chromeEngine, rulesEngine]`이고 WebLLM은 아직 없다.
- **WebLLM [결정, 2026-11-23]**: 모델을 기본으로 받지 않는 선택 사항이다. 사용자가 AI 설정에서 고르고 모델 받기를 누를 때만 받는다. 받기 전에는 자동 모드에서 건너뛴다. WebLLM 코드도 그때만 불러온다. 기본 모델은 다운로드 크기와 분해 품질로 고른다.
- **앱 (2단계)**: Gemini Nano(ML Kit GenAI, 지원 기종) → 기기 내 모델(MediaPipe, Qwen2.5 1.5B) → 기본 규칙.

자동 모드는 이 순서에서 바로 쓸 수 있는 첫 엔진을 고르고, 사용자는 AI 설정에서 엔진을 직접 고를 수 있다. 직접 고른 엔진을 못 쓰면 이유와 함께 기본 규칙을 쓴다.

### 구조

“규칙이 목표를 분석 → (AI가 있으면) 분석 결과 한 줄과 맞춤 예시로 AI에게 질문 → 규칙이 결과를 검사·보정”. AI가 없으면 같은 분석으로 규칙이 계획을 만든다. 규칙을 고치면 AI 경로와 규칙 경로 양쪽이 좋아진다. AI에게는 단계 제목만(최대 2단계 깊이) 받고, 예상 시간은 규칙으로 채운다.

### 엔진 인터페이스

현재 코드(`src/ai/types.ts`):

- `Engine { id: 'rules' | 'chrome' | 'gemini-nano' | 'native'; label; description; source; available() → {status: ready | needs-download | downloading | unsupported, reason}; download?(진행률, signal); decompose(req, signal) }`
- 요청 3종: `goal`(목표 나누기), `split`(단계 쪼개기: goal·step·minutes·path), `more`(더 제안: goal·existing·doneRatio).
- `decompose()`는 컨텍스트를 한 번 만들어 모든 엔진에 넘기고, 결과를 `refine`으로 검사한 뒤 `basis`(규칙 근거), `understood`(읽어 낸 정보), `fallbackReason`을 함께 돌려준다.

11-16 설계의 `DecomposeEngine`(availability, prepare, `parentPath`/`existing`/`count` 입력)은 현재 인터페이스와 거의 같다. 이름을 맞출지는 M5에서 정한다.

### 결과 검증

- 단계 수 최대 8개, 하위 최대 5개, 하위가 1개면 버림. 제목은 60자까지, 같은 제목은 하나만 남긴다. (구현됨)
- **[제안]** 단계가 2개 미만이면 실패로 보고, `minutes`는 1~240 사이 정수만 받는다.

### 실패 처리

- 60초 안에 결과가 없거나, 실패하거나, 읽을 수 없는 답이면 기본 규칙으로 대신하고 “(이유) 대신 기본 규칙으로 나눴어요”라고 알린다. (구현됨)
- 사용자는 언제든 멈출 수 있고, 멈추면 아무것도 저장하지 않는다. (구현됨)
- 새 목표는 미리 보기를 거쳐 저장한다. 더 쪼개기와 단계 더 제안은 바로 저장하고, 알림의 실행 취소로 되돌린다. (현재 동작)

## 완료 축하와 보상

완료 축하는 끝낸 단위가 클수록 강해지는 세 단계로 나눈다. 목표 완료 때는 스스로 정한 보상을 쿠폰처럼 보여 준다. **[결정]** 코드는 `src/reward/`에 있고 2026-11-23에 연결했다.

| 순간 | 화면 | 진동(Android Chrome만) |
| --- | --- | --- |
| 리프 하나 체크 | 체크박스가 톡 튐 | 짧게 한 번 |
| 부모 단계가 자동 완료 | “‘자료 조사’ 완료” 토스트 1.8초 | 두 번 |
| 목표 전체 완료 | 발자국이 섞인 색종이, 아래에서 올라오는 축하 창 | 길게 세 번 |

### 축하 창

- 목표 제목, “끝까지 왔어요”, 걸은 단계 수와 들인 시간을 보여 준다.
- 보상이 있으면 점선 쿠폰으로 보여 주고, “보상 받기”를 누르면 “받음” 도장이 찍힌다.
- 닫을 때 `celebratedAt`, 보상을 받을 때 `rewardClaimedAt`(과 `celebratedAt`)을 저장한다.
- 색은 앱 색(청록·황금색)을 따르고 다크 모드도 함께 바뀐다.

### 규칙

- 축하는 사용자가 직접 체크할 때만 일어난다(단계 체크박스, 일 페이지와 홈의 “끝냈어요”). 실행 취소, 가져오기, 마이그레이션에서는 일어나지 않는다.
- `celebratedAt`이 있는 목표는 다시 완료돼도 축하 창 대신 토스트만 띄운다.
- 실행 취소로 완료를 되돌려도 `celebratedAt`, `rewardClaimedAt`은 남긴다. 되돌린 뒤 다시 끝내도 축하 창이 또 뜨지 않게 하기 위해서다.
- 기기의 “동작 줄이기”가 켜져 있으면 움직임(이동·크기·회전) 없이 나타나고 사라지기만 한다 **[결정·구현됨, 2026-11-23]**:
  - 색종이 60개가 화면 위쪽 절반에 흩어진 채 제자리에서 0.6초 동안 나타나고, 2초 머물고, 1초 동안 사라진다.
  - 축하 창과 “끝까지 왔어요”, 받음 도장, 부모 완료 토스트는 서서히 나타난다.

## 저장, 백업, 마이그레이션, 실행 취소

데이터는 브라우저 안에만 있으므로, 지워지지 않게 요청하고 쉽게 내보낼 수 있게 하는 것이 저장 설계의 핵심이다.

### 영구 저장 [결정, 구현됨]

- 앱 시작 때 `navigator.storage.persisted()`를 확인하고, 아니면 `navigator.storage.persist()`를 요청한다. Chrome은 설치형 PWA처럼 참여도가 높은 사이트에 자동으로 허용한다.
- 설정의 “백업과 저장 공간” 화면에 보호 상태, 보호 요청 버튼, 사용량(`navigator.storage.estimate()`)을 보여 준다.

### 백업

- 백업은 권유하지 않는다 **[결정, 2026-11-23]**. 마지막 백업 시각은 정보로만 보여 주고 강조하지 않는다.
- “파일로 저장”, 휴대폰에서는 “공유하기”(파일 공유가 될 때만). 파일 이름 `halfstep-backup-YYYY-MM-DD.json`.

### 내보내기·가져오기 [결정, 구현됨]

- 내보내기 v2 형식: `{ format: 'halfstep', version: 2, exportedAt, goals, steps, templates }`. 설정은 포함하지 않는다. 내보낼 때 `settings.lastBackupAt`을 갱신한다.
- 가져오기는 v2와 예전 v1(트리 배열, `{goals:[...]}`도)을 모두 받는다. v1은 흔한 키 이름(title|text|name, children|steps|substeps|subSteps|items, done)을 너그럽게 읽는다.
- 망가진 데이터는 고쳐서 받는다: 없는 부모 → 최상위, 자식 있는 단계의 완료값 → null, 잘못된 source → manual, 잘못된 minutes·order 정리, 목표 없는 단계·제목 없는 것은 빼고 경고로 알림.
- 받지 않는 경우: JSON이 아님, 반걸음 형식이 아님, 더 새 버전, 가져올 것이 없음.
- 미리 보기(새로 들어갈 것, 건너뛸 것 개수)를 보여 준 뒤 한 트랜잭션으로 넣는다. 같은 id의 목표·템플릿은 건너뛰고, 다른 목표와 단계 id가 겹치면 새 id로 바꾼다.
- v2는 보상과 축하 기록을 그대로 옮긴다. v1에서 온 목표는 축하를 본 것으로 둔다.

### localStorage에서 옮기기 [결정, 구현됨]

최초 한 번, `settings.migratedFromLocalStorage`가 없고 localStorage에 `halfstep:goals:v1`이 있으면 실행한다.

1. 트리를 순회해 평평하게 만든다. `order` = 형제 순서 × 1000.
2. 완료된 리프의 `doneAt` = 그 목표의 `updatedAt`(실제 완료 시각을 모름). 부모의 `doneAt` = null.
3. 모든 단계의 `source` = 'legacy'.
4. `halfstep:engine` 값(auto|chrome|rules)을 `settings.enginePref`로 옮긴다.
5. 옮긴 목표는 `celebratedAt`을 지금 시각으로 채워, 이미 끝난 목표에 축하가 뜨지 않게 한다.
6. 끝나면 플래그를 저장한다. 망가져 있어도 경고만 하고 계속한다. localStorage 원본은 당분간 지우지 않는다.

### 실행 취소 [결정, 구현됨]

- 메모리 스택, 최대 30개. 쓰기 직전에 해당 목표의 행과 그 목표의 단계 전체를 스냅샷으로 남긴다. 실패한 쓰기는 쌓지 않는다.
- 되돌리기는 한 트랜잭션에서 그 목표의 단계를 지우고 스냅샷을 다시 넣는다. 목표 삭제였으면 목표 행도 다시 만들고, 새 목표 만들기였으면 목표를 지운다. `celebratedAt`, `rewardClaimedAt`은 지금 값을 유지한다.
- 접기, 홈 고정, 템플릿 변경은 기록하지 않는다.
- 새로고침하면 스택은 비워진다.
- **다시 실행 [결정·구현됨, 2026-11-23]**: 확인 창 대신 다시 실행을 둔다. 되돌리기 직전 상태를 다시 실행 스택(최대 30)에 쌓고, 새 작업을 하면 비운다. 위쪽에 “실행 취소”·“다시 실행” 버튼(휴대폰은 ↶ ↷ 아이콘), 되돌린 직후 알림의 “다시 실행” 버튼, Ctrl+Shift+Z·Ctrl+Y. 다시 실행해도 축하는 뜨지 않는다. (처음에는 “정말 되돌리겠습니까?” 확인 창으로 정했다가, 습관적으로 “예”를 누르게 된다는 이유로 바꿨다.)
- 더 쪼개기와 단계 더 제안은 미리 보기 없이 바로 저장하고, 실행 취소로 되돌린다. **[결정, 2026-11-23]**

## 배포와 PWA

- vite-plugin-pwa(generateSW, autoUpdate). 매니페스트: 반걸음, standalone, 세로, `start_url`·`scope`는 `./`(어느 하위 주소든 맞음). 아이콘: 192·512·maskable·apple-touch·favicon.svg(짙은 바탕에 황금색 반원). `src/pwa.ts`가 서비스 워커를 등록하고, Capacitor 앱 안에서는 등록하지 않는다.
- `vite.config.ts`의 base는 `BASE_PATH` 환경 변수(기본 `/`). #-라우팅이라 base 주소 하나면 된다.
- **배포는 GitHub Pages로 한다 [결정, 2026-11-23]**. 공개 저장소라 무료다(비공개 저장소는 유료 플랜 필요). Replit(보내는 데이터 양만큼 요금)에서 바꿨다.
- `.github/workflows/deploy.yml`: main에 올리면 npm ci → npm test → 빌드(저장소 이름으로 BASE_PATH 자동) → GitHub Pages 배포. 저장소 Settings → Pages → Source를 “GitHub Actions”로 한 번 바꿔야 한다. 주소는 `https://아이디.github.io/저장소이름/`.
- git 저장소는 2026-11-23에 만들었다(브랜치 main). 개인 백업 파일(`halfstep-backup-*.json`)은 `.gitignore`로 올리지 않는다.
- 아직 실제로 배포하지는 않았다.

  - `LocalLlmPlugin.java`: MediaPipe LLM Inference로 기기 내 AI. 모델 다운로드(이어받기), 불러오기, 생성, 지우기.
  - 기본 모델은 Qwen2.5 1.5B(.task, 약 1.6GB). 0.5B는 분해 품질이 부족하다고 판단했다.
